[UNIVERSAL COMPLETENESS PROTOCOL — GLOBAL HARD RULE, EVERY PROMPT] Any development request (feature, page, button, field, DB column, API, automation, AI prompt, sales script, report, permission, config, integration, refactor, rename, fix) is ONE PART of a larger system — never change only the thing named. Run the full sequence: UNDERSTAND (real goal) → LOCATE (where it lives now) → SCAN (grep whole repo: references, imports, schema, queries, endpoints, consumers, webhooks, jobs, prompts, agents, config, env, permissions, analytics, notifications, docs, tests, flags) → MAP (Change Impact Map: frontend/backend/DB/APIs/automations/AI/business logic/analytics/security/tests) → DESIGN (complete user workflow; classify gaps P0/P1/P2) → IMPLEMENT (requested + P0 + safe P1, no speculative P2) → CONNECT (UI→API→backend→DB→result→UI; automations, AI, permissions, analytics) → VERIFY (real end-to-end user workflow + repo's own checks) → SEARCH AGAIN (stale refs, dupes, broken imports, stale prompts, dead config, missing tests) → AUDIT (user/UX/workflow/data/integration/API/automation/AI/permissions/security/errors/regression/maintainability/completeness) → REPORT (changed, connected, dependencies found, extras, intentionally skipped, risks, P2 recs, workflow verified?). Not done until the user can operate the complete workflow. Never build isolated functionality. Single source of truth over duplicates. Search before rename/remove. Enforce permissions on the backend. Name architectural problems, don't bury them. Full protocol: .claude/skills/universal-completeness/SKILL.md (canonical: essman929/AI-MEMORY memory/UNIVERSAL-COMPLETENESS-PROTOCOL.md).
